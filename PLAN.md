## 0. Что это

**CryptoSwap** — обменник валют: фиат → крипта, крипта → фиат, крипта → крипта.
Пользователь выбирает валюту "отдаю" и валюту "получаю", вводит сумму, видит курс
и итоговую сумму к получению (с учётом комиссии), может создать заявку на обмен.

**Важно: это НЕ реальный обменник с реальными деньгами.** Это демонстрационный
портфолио-проект — заявки создаются, курсы реальные (публичное API), но фактического
перевода средств не происходит (нет интеграции с реальными платёжными провайдерами/
крипто-кошельками с приватными ключами). Это должно быть явно и честно написано в
README и, если есть смысл, в UI (баннер, как в PulseOps: "Demo — no real funds move").

**Портфолио-цель:** отдельный проект от PulseOps (другой домен: не SaaS-аналитика,
а финтех/обменник), чтобы показать широту. Одна четкая история, не смешивать с
другими проектами.

## 1. Легенда / позиционирование (придумать так же честно, как в PulseOps)

Перед началом реализации определить и вписать в README:
- **Что это:** свой pet/MVP-проект обменника (аналог small crypto exchanger типа
  простых сайтов-агрегаторов курсов).
- **Для кого:** обычные пользователи, которым нужно быстро прикинуть курс обмена
  фиат↔крипта или крипта↔крипта без захода на биржу.
- **Проблема:** курсы разбросаны по разным сайтам/биржам, нет единого удобного
  калькулятора с историей заявок.
- **Решение:** один экран — выбрал валюты, увидел живой курс и сумму, создал заявку
  (демо, без реального перевода денег).
- **Твоя роль:** соло — продукт, дизайн, фуллстек.

НЕ выдумывать реального работающего биттех-бизнеса с реальными объёмами/клиентами —
это создаст регуляторные вопросы на собеседовании (обмен крипты требует лицензий
в реальном мире). Чётко: "pet-проект/MVP, демонстрирует техническую реализацию
конвертера, без реальных переводов денег".

## 2. Функциональные требования

- [x] Выбор направления обмена: селекторы валют покрывают Fiat→Crypto,
      Crypto→Fiat, Crypto→Crypto (единый список валют, любая пара)
- [x] Селекторы валюты "отдаю" / "получаю" (тикер + название)

      реальной валидации платёжных данных)

      (автозавершение через 15 секунд, `/history`)
- [x] Страница отдельной заявки с деталями (`/exchange/[id]`)

### 2.2 Расширенный функционал (после MVP, по желанию)
- [ ] График истории курса выбранной пары (последние 7/30 дней)

      биржи)
- [ ] Уведомление/алерт "сообщить, когда курс достигнет X" (демо, без реальной
      отправки писем — или через email-сервис, если есть время)
- [ ] Мультиязычность (en/ru) — если будет время
- [ ] Тёмная/светлая тема (как в PulseOps — переиспользовать паттерн, если стек

### 2.3 Явно НЕ делать (осознанно вне скоупа)
- Реальную интеграцию с платёжными системами / крипто-кошельками с приватными

- Хранение реальных средств пользователей
- Реальные выводы/переводы денег

## 4. Источник данных о курсах (ключевой технический вопрос)

Нужны два типа курсов:
1. **Фиат↔фиат / фиат↔крипта** курсы
2. **Крипта↔крипта** курсы

### Рекомендуемые бесплатные API (проверить актуальность на момент реализации,
### у всех есть free tier):

- **CoinGecko API** (`api.coingecko.com`) — бесплатно, без API-ключа для базовых
  запросов, даёт курсы крипты к фиату и крипты к крипте (через фиат-мост).
  Простой и надёжный вариант для старта — **рекомендуется как основной источник**.
- **exchangerate-api.com** или **Frankfurter API** (frankfurter.dev, бесплатно,
  без ключа) — для чистых фиат↔фиат курсов, если нужны отдельно от крипты.
- **CoinMarketCap API** — тоже есть free tier, альтернатива CoinGecko.

**Архитектурное решение:** курсы запрашивать на **сервере** (API route/Route
Handler), не с клиента напрямую — чтобы (а) спрятать API-ключ, если он нужен,
(б) закэшировать на несколько секунд/минут и не упираться в rate-limit,
(в) держать единую точку, откуда UI берёт данные (легко подменить провайдера).

Пример потока:
```
Клиент → GET /api/rates?from=BTC&to=USD → сервер идёт в CoinGecko (с кэшем
in-memory/Redis на ~30-60 сек) → возвращает { rate, updatedAt }
```

Курс "крипта → крипта" считать через кросс-курс к общей базовой валюте (USD):
`rate(A→B) = rate(A→USD) / rate(B→USD)`.

## 5. Доменная логика (то, что тестируется на 100%, по аналогии с PulseOps)

Вынести в чистые функции без побочных эффектов (легко покрыть Vitest):

```
computeExchangeAmount(input: {
  amount: number;
  direction: "give" | "receive"; // с какой стороны введена сумма
  rate: number;        // курс "отдаю"→"получаю", по данным API
  feePercent: number;  // комиссия обменника, например 1.5
}): {
  giveAmount: number;
  receiveAmount: number;
  feeAmount: number;
  effectiveRate: number; // курс с учётом комиссии
}
```

```
computeCrossRate(rateAtoUSD: number, rateBtoUSD: number): number
// курс A→B через общую базу USD
```

```
validateExchangeRequest(input): { valid: boolean; errors: string[] }
// валидация суммы (мин/макс лимиты), валют (пара поддерживается), и т.д.
```

Эти функции — ядро приложения. Именно они должны быть покрыты тестами на 100%,
аналогично `computeAnalytics`/`computeMrrMovement`/`computeCohortRetention` в
PulseOps. UI и API routes — тонкий слой поверх них.

## 6. Структура данных заявки на обмен

```ts
type ExchangeRequest = {
  id: string;
  createdAt: Date;
  status: "pending" | "completed" | "cancelled"; // demo-статусы, без реальной обработки
  giveCurrency: string;    // напр. "BTC"
  receiveCurrency: string; // напр. "USD"
  giveAmount: number;
  receiveAmount: number;
  feeAmount: number;
  rateAtCreation: number;  // зафиксированный курс на момент заявки
  recipientContact: string; // demo: email или произвольная строка, без реальной валидации платёжных реквизитов
};
```

## 7. Экраны / маршруты

- `/` — главный экран калькулятора (выбор валют, сумма, курс, кнопка создать заявку)
- `/exchange/[id]` — детали конкретной заявки, статус

- `/rates` (опционально, расширенный функционал) — таблица всех поддерживаемых валют с курсами
